# 分步执行计划

> 2026-09-17范围更新：用户确认与CanDo无关，改用小红书公开笔记验证通用文字/多图流程；视频和ASR暂缓。下文保留原始完整计划及长期质量目标，CanDo专用前置不再阻塞当前开发。当前实现与逐项限制以[公开笔记验收记录](10-public-note-pilot.md)和[当前进度](07-status.md)为准，未实施的长期试点不能标为通过。

状态来源：[当前进度](07-status.md)。v0.3.0 已交付 S1 契约、S2/S3 本地核心与 S4 研究工程，S4 真实质量验收仍待完成；下列各阶段保留完整目标，不代表全部验收已经完成。工时是单名开发者的有效工作日估计。开发者负责实现与自检；产品负责人负责确认事实、标注质量样本和签署阶段验收，同一人可兼任。所有阶段结果填入 [验收记录模板](../templates/acceptance-record.md)，未执行的检查不能填通过。

依赖顺序：S0 → S1 → S2 → S3 → S4 → S5 → S6 → S7；S8 仅在 S7 证明价值且来源许可完备后进行。每阶段通过后继续下一阶段；只在缺真实资料、产品事实或外部授权时等待相应输入，不需要为每项可逆开发操作额外停工。

## S0：项目与方案建立（已完成）

- 输入：用户方案、空项目目录。
- 执行：建立 Git/Python CLI 骨架；核验关键外部事实；明确 MVP、架构、工期与验收；保留合成示例。
- 产物：README、docs、templates、examples、配置示例、uv.lock、离线检查脚本。
- 验收：`uv sync --locked`、`uv run rednotebook doctor`、`uv run rednotebook status`、`uv run python scripts/check_scaffold.py` 成功；文档本地链接有效；status 不冒充实现研究功能。
- 完成不代表：真实数据、Agent、审核或图文已实现。

## S1：范围、许可与评估基线（1–2 天）

- 输入：CanDo 当前版本资料；至少一个来源许可清单；可用本地模型信息。无真实资料时仅搭合成夹具。
- 执行：填 brief；把每条产品功能标成已验证/待验证并绑定截图；建立字段字典与 SourceGrant；收集 30–50 篇获准笔记、100–200 条评论，分别标热门/近期样本；记录人工做一轮的时间与质量。
- 产物：`private/pilot/brief.json`、`facts.json`、`source-grants.json`、受控样本、基线表；Git 仅保存合成夹具和字段契约。
- 验收：A01、A02；所有真实资料均有许可状态，unknown 不进入对应处理；产品事实无无证据的 verified；覆盖不足如实记录。
- 退出条件：无法获得获准样本，真实研究分支暂停，不阻塞 S2/S3 合成开发。

## S2：结构化导入与证据存储（3–4 天）

- 依赖：S1 字段契约冻结。
- 执行：引入并锁定 Pydantic；建 SQLite 迁移；实现 JSON/CSV 映射、原始值保存、行级校验、去重、修订、快照与导入事务；实现质量报告和来源撤销。
- 产物：`rednotebook import --file … --grant …`、`rednotebook evidence inspect …`（均为计划命令）；迁移、样例与自动测试。
- 验收：A03–A06、A16；200 笔记/500 评论夹具重复导入无重复，坏行定位准确，历史快照不丢，来源撤销使派生物失效。
- 失败恢复：批次原子回滚或显式 partial 并记录逐行状态；不得悄悄只导入一半后返回 complete。

## S3：采样覆盖与确定性指标（2–3 天）

- 执行：实现独立作者/笔记去重、热评/新评/回复覆盖统计；固定可比组；实现平均秩分位、完整案例筛选、快照差值和分母检查。
- 产物：`rednotebook metrics …`、`quality.json`、`sampling.md`、指标单元测试。
- 验收：A07–A09；手算黄金样本一致；组内不足 20 条输出 insufficient_cohort；缺数据不产生零或伪 CTR；近似指标明确标记。
- 决策：如果大量记录无法形成可比组，保留原始分布和描述，不用放宽口径强行生成评分。

## S4：有引用的研究 Agent（4–6 天）

- 输入：S2/S3 可用，本地模型端点及来源处理许可已明确。
- 执行：完成模型能力探针；锁定 Pydantic AI；实现结构化发现、引用验证、反例状态、假设降级；网关白名单；预算/超时/重试；记录模型/提示/输入哈希。
- 产物：`rednotebook analyse --brief …`、研究报告、评估运行记录；无模型时显式失败或只提供证据整理结果。
- 验收：A10–A12、A15；人工评估引用支持关系精度≥90%，严重虚构为零；不存在的引用直接拒绝；恶意评论不能触发联网或修改。
- 决策：两轮修正仍不达标，降级为半自动证据整理，不进入自动创意承诺。

## S5：真实产品约束下的创意和分镜（3–4 天）

- 执行：将 verified 产品事实与发现作为允许引用集合；输出问题共鸣/具体机制/操作方法三个方向；选择一套六页分镜；每页说明信息任务、素材、事实、待补项；相似文本检测输出证据供人工复核。
- 产物：`rednotebook propose …`、`proposals.json`、`storyboard.json`、素材缺口清单；可选视觉分析探针。
- 验收：A13；零未验证产品承诺、零伪造用户反馈；每个方向有验证目标；不足时允许少生成并解释原因；没图不声称看过图。
- 决策：CanDo “未完成事项延续到次日”等行为未实测时只列待验证方向，禁止导出为已实现宣传。

## S6：审核、图文导出和交付（4–6 天）

- 执行：实现数据库审核状态机、版本/素材哈希、固定版本导出；引入锁定版本的 HTML/CSS 模板渲染器（优先 Playwright）；中文字体随部署明确；自有截图原样嵌入；受控输出目录，禁止脚本/外链执行。
- 产物：`review`、`preview`、`export` 命令；六张 PNG、正文、manifest、声明提示、来源说明；渲染与审核集成测试。
- 验收：A14、A17、A18；篡改/旧批准/未批准导出拒绝；截图与长标题人工目视检查；相同版本重试不重复产物；元数据无秘密；整条导入至导出链通过。
- 发布边界：软件交付为导出包；真实平台发布由作者审改并操作。S6 是工程 MVP 完成点。

## S7：自有数据复盘与价值验证（2–3 工作日 + 2–3 周观察）

- 执行：实现自有后台导入与 proposal_version 关联；记录实际发布时刻和 24h/72h/7d 快照；完成三个真实 brief 的人工基线对比；作者自主安排 3–6 篇真实内容发布，记录制作时间、有效讨论、产品兴趣及归因条件。
- 产物：`outcome import`、`retrospective` 命令、试点复盘和 go/adjust/stop 决策。
- 验收：A19、A20；没有自有数据时记待验收；缺失窗口不插值伪造；用时目标和质量门槛同时检查。发布量不足不能冒充完成效果验证。
- 决策：研究/创作时间有明显节省且质量达标，才评估 S8；传播效果没有改善并不自动否决工程价值，但需调整内容假设。

## S8：可替换只读数据源（可选，每个 5–10 天）

- 前置：S7 价值通过；确切来源访问、存储、处理许可完备；第三方依赖许可证按固定版本审查。
- 执行：先合同明确的接口；再评估浏览器研究适配器。显式映射只读操作、预算、缓存、断点和错误分类；按适配器契约返回标准对象，不让第三方类型穿透领域层。
- 产物：一个适配器、字段映射、权限清单、固定版本记录、故障演练。
- 验收：A21；401/403/429/验证码/字段变化模拟通过；禁写工具；停用适配器后导入主链仍能运行。
- 后续：是否增加每周规则变更提醒另按需求配置；当前计划不创建定时任务。

## 所有阶段的完成定义

代码、迁移、使用说明、与本次变化相关的测试一并交付；记录实际命令、环境、结果、失败和限制。严重事实错误、权限穿透、版本错误导出、数据丢失属于阻断项，不用平均分抵消。计划命令在实现前不标成可运行。
