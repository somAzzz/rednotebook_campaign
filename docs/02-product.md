# 产品范围与需求

## 用户与任务

第一用户是独立开发者/内容作者，适用于一般项目和个人内容。CanDo仅保留为历史合成夹具名称。目标是在固定预算内完成一轮可追溯研究，提出与真实产品一致的创意，输出便于人工审改的文案和分镜，并记录后续表现。

主流程：整理作者目标与材料 → 按需研究获准资料 → 策划本帖与后续职责 → 生成发布稿 → 程序检查、模型辅助审阅与作者确认 → 批准确切版本 → 导出。真人发布与效果复盘按需进行。兼容的研究摘要仍使用六页；新发布稿使用1–20页。

## 第一版需求

| ID | 功能 | 可观察结果 |
|---|---|---|
| R01 | Brief 与产品事实 | 人群、问题、目标、禁用说法、事实版本、素材缺口均可查看 |
| R02 | 导入与去重 | JSON/CSV 行级错误报告，重复导入不复制证据，快照保留历史 |
| R03 | 证据与覆盖 | 来源、采样词/排序、观察时间、作者去重、评论截断可追溯 |
| R04 | 指标比较 | 缺失不补零，缩写保留原文，可比组和计算版本可查看 |
| R05 | 研究报告 | 讨论/表达分开；每条发现有支持、反例状态、范围、局限 |
| R06 | 创意方案 | 通常三方向；每个含需求证据、产品事实、标题、正文、测试目标；不足时允许少于三个 |
| R07 | 分镜与导出 | 按内容选择1–20页 1080×1620 PNG、文案、清单、来源说明；旧研究摘要六页 |
| R08 | 版本审核 | 修改使原批准失效，拒绝导出未批准版本；草稿预览明显标识 |
| R09 | 复盘 | 手工录入发布关联，24h/72h/7d 的实际观察时间与缺失说明 |
| R10 | 预算与安全 | 超限部分完成；只读网关；凭据不进入模型与普通日志 |

MVP 不包含自动发布、互动、账号批量运营、验证码绕过、全站采集、投放优化、爆款概率、复杂 Web 工作台、多租户和自动定时监控。视觉模型是可选增强：未实际读取图片时写“未做视觉分析”，不能根据标题编造。

## 输入与产出约定

作者创作输入使用 ContentBrief，研究引用可为空；陈述、硬件持有、各项目进度与测试结果独立。研究分支仍需 ResearchBrief、来源许可和获准证据，保留指标口径与评论覆盖。空研究集不输出虚构发现，但不阻止原创策划。

每轮产出：`quality.json`、`research.md`、`findings.json`、`proposals.json`、`storyboard.json`、审核记录、`export/manifest.json`、文案与 PNG。复盘另产 `outcomes.csv` 和 `retrospective.md`。这些是原始目标文件命名；当前产物以版本化bundle及受管导出为准，使用方式见[策划实施说明](15-campaign-implementation.md)。

## 三层成功标准

工程：输入可重放、证据可追溯、权限和版本约束有效、异常不伪造成功。

内容质量：人工抽审支持关系精度至少 90%，所有事实性产品说法都能绑定已验证事实；严重虚构零容忍。具体样本与计分见验收方案。

工作价值：以三个真实 brief 进行同范围人工基线对比，研究至可审草稿的主动用时中位数减少至少 30%，作者对可用性评分至少 4/5，且无严重事实错误。这些是试点目标，未达标需修订范围。

传播效果仅作为探索结果；几篇自然发布不能构成因果实验，不能用点赞增长替代上述质量门槛。
