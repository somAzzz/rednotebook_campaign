# MCP 自动检索、完整采集与研究总结审核标准

制定日期：2026-09-18。

本文件定义后续实现与验收的目标，不表示当前代码已全部达到要求。适用于“扫描约30–40篇候选、选择3–5篇精读、形成研究总结并按需策划”的工作流。既有使用说明见[主题研究流程](17-topic-research.md)，长期研究质量标准见[验收方案](05-acceptance.md)。

## 1. 核心放行原则

**每篇计入精读完成的图文笔记，必须完整保存标题、展开后的全部正文及全部图片，并完成逐图内容读取与核对。评论允许有界抽样，不要求全量。**

完整的范围是观察时刻该笔记获准访问的标题、正文和图片内容，不包含广告、推荐流或其他笔记。隐藏、不可访问、加载失败的内容不能假定为空；必须记录缺口，不能声称“全部采集”。视频不在本流程处理范围内。

“保证完整”通过可核对的清单、逐项证据和不完整时拒绝放行实现，不能通过模型自称“读完了”或任务返回complete实现。数量齐全、原文保存完整、图片读取正确是三项独立检查。

## 2. 分阶段审核

| 阶段 | 审核要求 | 放行条件 |
|---|---|---|
| 意图规划 | 保留原始主题、用户目标及任务深度；扩展词标为探索方向 | 不替换核心主题，不把扩展品类属性当作主题事实 |
| 候选扫描 | 目标约30–40篇去重候选，保存查询来源、时间和原始显示指标 | 报告实际数量；不足时说明，不反复凑数或宣称平台全量 |
| 样本选择 | 原则上3–5篇，覆盖用户问题、具体经验及不同观点 | 每篇有入选理由、待回答问题；不能仅按卡片数字排序 |
| 正文采集 | 标题、正文展开、尾部核对、原文保存 | 全文完整性检查通过，未截断，无未解决的隐藏内容 |
| 图片采集 | 独立确认总数、按页保存、核对实际页面与文件 | 所有页位都有正确且可解码的文件，缺页为0 |
| 逐图阅读 | 全部图片按页分析；文字提取与视觉内容分开保存 | 每页有读取结果，关键文字核对通过；识别缺口未被猜测填补 |
| 评论抽样 | 少量高讨论度评论及必要上下文 | 记录抽样范围、选择依据和缺失指标，不影响正文图片完整性判断 |
| 研究总结 | 使用完整精读材料，保留引用、分歧和限制 | 重要结论均可追溯，没有把搜索标题、作者自述或模型推断当作验证事实 |
| 策划接入 | 使用真实研究与来源依赖，保留用户主线 | 完整性门槛通过后才按“研究后策划”放行；作者材料模式独立 |

候选扫描只读取卡片，不要求把30–40篇都完整下载。完整采集要求适用于最终计入精读的每篇笔记。

## 3. 标题与正文完整性

必须同时满足以下要求：

1. 页面笔记ID与目标笔记一致，详情已加载，标题与正文来自正确的详情容器。
2. 识别并展开“展开全文”等正文折叠状态；滚动或展开操作不得误触视频、评论互动或其他笔记。
3. 保存展开后的标题及正文原文，包含段落、列表、标签、链接显示文字、数字和单位。仅允许预先定义的换行/空白规范化，不静默删除内容。
4. 保存正文长度、内容哈希、观察时间、展开状态及核对依据。哈希只能证明保存后未改变，不能单独证明没有漏采。
5. 与完整展开后的页面核对首尾和中段；验收样本必须逐段比对。两次读取稳定可辅助判断加载完成，但“稳定”不等于“完整”。
6. 无文字正文的笔记可以通过，但必须明确确认正文为空；选择器失败、正文未加载与空正文必须区分。
7. 模型输入长度限制不能丢弃正文。长文本应完整保存并分段读取，保留段落位置和引用映射，不能只研究首段后声称已读全文。

存在未展开正文、正文末尾缺失、跨笔记串文或未解释的截断时，本篇不得计为精读完成。

## 4. 全部图片的采集与读取

### 4.1 确认数量和逐页保存

- 从页码指示、有效分页列表等页面证据确认总数N；无分页点不等于没有图片，也不等于只有一张。
- 明确无图时N=0；总数无法确定时N=null，完整性状态为unknown，不能用已下载数量反推总数。
- 必须保存位置1至N的全部图片，并保留页序。不能以“只取封面”“只取前几张”或默认max_images上限宣称整篇完整。
- 如果N超过当前能力或显式上限，应返回partial及缺失页位；不得修改N来匹配下载数量。后续实现需要支持完整采集或明确拒绝本篇完整验收。
- 每次翻页确认活动页位已切换，等待该页图像就绪后再取资源；仅等待固定时间或发现任意可见图片不足以证明翻页成功。
- 每页记录页位、文件、哈希、像素尺寸、解码结果和采集时间。保存详情实际展示的完整图像资源，不能拿封面缩略图、裁切预览或截图替代原图并称为完整图片。
- 若平台只提供受限分辨率，记录实际可取得资源与限制；文字因此无法辨认时，不能通过完整阅读验收。
- 下载字节必须能解码为图片。HTML错误页、空文件、损坏文件均为失败。目标格式需要特殊解码时明确报告，不假装成功。

**图片采集通过条件：总数已确认，页位集合恰好为1…N，每个页位对应正确且可解码的完整图片，未解决缺页与错页均为0。**

不能只比较文件数量。若多页误保存为同一张旧图，即使数量相等也不通过。真实重复图片允许存在，但每个页位都应有独立的页面核对依据；哈希去重不得删除真实页位。

### 4.2 逐图阅读与图片内文字

采集完成后仍需独立检查阅读完成：

- 所有页位都必须有图像分析结果；纯照片也应记录视觉内容，不因没有文字而跳过该页。
- 图片中的正文、标题、表格、图注、脚注、数字和单位均属于读取范围。全文转写与摘要分开保存，摘要不能替代原文。
- 长图、小字或表格需要分块放大读取时，保留原图及块与原页的位置映射，避免遗漏底部、边缘或跨块段落。
- 机器识别文本明确标记为机器提取，不冒充作者原始文本；模型返回成功不证明识别正确。
- 验收时逐页对照图片核对文字。所有可辨认文字不得有未解决的漏段；影响理解的数字、单位、否定词、条件和表格关系必须正确。
- 无法辨认的文字明确标注位置和原因，禁止猜写。影响研究问题的内容未能读取时不放行；若要求“所有图片文字已完整读取”，任何未解决的文字缺口都不能标为complete。

图片文件完整保存、机器读取完成、人工核对通过必须分别报告。程序只能保证已执行相应检查，不能替代真实图片识别准确率验收。

## 5. 评论抽样：少量高讨论度评论

默认目标为3–5条有内容的一级评论，并在理解观点所需时补充有限回复；条数可随实际可用内容调整。正文和图片采集优先，评论失败不得被混同为正文缺失。

选择依据按可取得的信息使用：

1. 有明确定义且可读取的回复数时，优先考虑回复较多、讨论具体问题的评论。
2. 回复数相同或缺失时，可参考明确标识的点赞数、平台热评排序及与研究问题的相关性。
3. 无可靠数值或排序依据时，只能称为“可见评论中的相关讨论样本”，不能称为“讨论度最高的评论”。置顶和页面前几条不自动等于高讨论度。
4. 尽量涵盖疑问、实际经验和不同观点；剔除纯广告及无信息内容。人工/模型相关性选择记录理由，不伪装成客观排名。

保存被选评论的完整可见文字、ID或可追溯位置、父子关系、观察时间、实际可见点赞/回复指标及精度。缺失为null，不能补0。回复只采集理解讨论所需的部分，并标明线程截断；不要求展开全部评论。

评论报告至少包含：浏览了多少条（无法确定则unknown）、选择多少条、排序/选择依据、是否置顶、是否截断、评论加载限制。选择范围是本轮实际浏览的评论，不能声称整篇或平台全量排名。没有评论与无法加载评论需要区分。

**评论抽样数量不足不单独阻断正文图片完整性通过；但缺少评论证据时，不得输出“读者最关心”“评论区普遍认为”等结论。**

## 6. 完成状态与策划门槛

建议后续实现分别记录以下状态；这些是目标字段含义，不是宣称当前已经有同名接口：

| 检查项 | 状态示例 | 解释 |
|---|---|---|
| 正文采集 | complete / partial / unknown | 已展开且核对完整，或明确存在/无法排除缺口 |
| 图片采集 | complete / partial / unknown | N=0且确认无图可通过；N未知不可通过 |
| 图片读取 | complete / partial / not_applicable | 所有页读取完成；确认无图才是不适用 |
| 文字准确性审核 | passed / needs_review / not_run | 与采集及模型执行完成分开 |
| 评论抽样 | sampled / none_confirmed / unavailable / not_requested | 抽样不冒充全量采集 |
| 研究执行 | complete / partial / failed | 仅代表研究任务执行情况 |
| 本篇完整性门槛 | passed / blocked | 综合正文、全部图片与读取缺口判断 |

进入“完整精读已完成”的样本集合，必须通过本篇完整性门槛。进入“已验收”的集合，还必须通过对应人工核对。最终3–5篇中每篇都按同一标准检查；不足时报告实际完整数量和缺口，不能把partial或视频凑入完成数。

运行时应把上述完整性门槛接入research_complete/campaign_ready判定。仅有子任务state=complete或run_id不够。部分材料可保留并形成明确受限的报告，但不能冒充用户要求的完整精读和研究后策划验收。

恢复必须沿用正确笔记、来源和采集版本；混合不同时刻页面内容时记录版本变化并重新核对数量与页序。暂停不绕过，失败不无限重试。来源撤销或到期后，原文、图片、提取文字、研究及策划依赖按现有机制失效和清理。

## 7. 验收用例与通过标准

| ID | 场景 | 必须观察到的结果 |
|---|---|---|
| C01 | 折叠长正文，含标签、链接、单位与否定句 | 展开后逐段完整保存；分段研究覆盖全文 |
| C02 | 确认无正文/无图片，与加载失败分别测试 | 真正为空可通过；未知或失败不能记0、不能通过 |
| C03 | 单图无分页、普通多图、长图和20张图 | 数量有独立依据；1…N逐页保存、读取、核对 |
| C04 | 总数超过上限、漏最后一张、某页损坏 | 明确partial和缺页；不能标完整精读或策划就绪 |
| C05 | 翻页延迟导致仍显示上一张，另含真实重复图 | 识别错页；真实重复内容保留不同页位 |
| C06 | 图片含小字、表格、脚注和长图底部文字 | 必要时分块读取；不漏段，关键数字/条件正确 |
| C07 | 下载成功但返回HTML、缩略图或裁切资源 | 不通过完整图片验收；保留具体原因 |
| C08 | 评论置顶、热评、未知指标、少于3条和无评论 | 抽样依据可追溯，缺失不补0，不声称全量最高 |
| C09 | 视频卡片与进入详情后才识别的视频 | 不播放、不处理视频；跳过且不计精读完成 |
| C10 | 中途失败、取消、重启和显式续跑 | 保存已有证据；不把缺页标成功，不重复已完成步骤 |
| C11 | 引用来自不同笔记或遗漏条件、否定句 | 拒绝错误引用或退回修订，不用引用存在代替语义支持 |
| C12 | 来源撤销/到期，或缺许可 | 拒绝访问，派生材料失效；不泄露采集签名地址 |
| C13 | 全流程扫描→精读→总结→策划 | 实际数量和逐篇完整性一致；总结附来源、分歧和限制 |

离线工程验收使用临时数据库、本地页面和合成图片，覆盖全部适用用例。每个故障用例必须验证“不会错误放行”，不仅验证存在错误提示。

真实验收至少完成两轮不同主题的完整流程，每轮扫描目标30–40篇、精读3–5篇，并逐篇逐页人工核对。样本应覆盖有折叠长正文、单图、多图、长图/小字/表格以及有限评论；真实缺少的边界样本可以离线补测，但必须标注未通过该项真实验收。

采集硬指标：验收样本正文完整率100%、图片正确页位覆盖率100%、可解码率100%，无未说明截断、无缺页错页、无串笔记。图片文字按逐页核对要求执行；发现遗漏必须修复并重验该篇。研究引用可解析率100%，严重虚构为0；研究语义支持精度与更大规模质量验收沿用既有A11标准，不能用这两轮小样本替代。

## 8. 单篇与整轮验收记录模板

每篇记录以下字段，可另存为受管JSON或人工验收表；实际持久化方案改变时需做迁移及来源撤销审查：

- 版本与身份：代码版本、模型/提示版本、任务ID、来源ID、笔记ID、公开链接、观察时间、验收人和时间。
- 正文：是否展开、原文长度/哈希、原文位置、首尾及逐段核对结果、截断或缺失说明。
- 图片：确认总数及其依据；每页文件/哈希/尺寸/解码状态、页面对应核对、提取文字/视觉分析位置、识别疑点；缺页和错页列表。
- 评论：浏览范围、选中数量、排序/选择依据、所选评论与必要回复、指标缺失和线程截断。
- 研究：研究ID、主要结论与支持/反对引用、未解决问题、总结适用范围。
- 结论：采集完整性、读取完整性、人工准确性审核、是否计入完成样本、阻断原因与复验记录。

整轮记录扫描实际数、入选数、视频跳过数、完整精读数、未完成列表、总结/策划确切版本及每项验收结论。报告中不能出现“所有步骤完成”而清单仍有未解决缺页或文本截断。

## 9. 当前实现差距与后续审核重点

根据本次代码检查，以下要求尚不能视为已实现或已验收：

- 正文目前主要读取详情DOM的innerText；尚无独立的全文展开与逐段完整性证明。
- 图片采集已有分页、页位、文件哈希和上限检查，但总数依据、无分页单图/无图判定、翻页后是否仍取到旧图及完整分辨率仍需按本标准核验。
- 当前关闭图片采集可以返回complete；在本标准下不能据此放行完整精读。
- 图片分析成功不等于所有文字识别正确；需要明确分段覆盖与逐页人工验收。
- 评论目前按页面可见顺序和上限截取，尚不具备可靠的高讨论度选择依据，不能称为已实现热评筛选。
- 主题策划门槛已有任务完成检查，但需要补充正文和全部图片的独立完整性检查。

本次交付是审核和验收标准文件，未修改采集行为、未运行真实采集、未将上述差距标记为已修复。
